## ❓ Open Questions

1. **When does the outer loop become fully trustworthy without human oversight?** Dreaming automates cross-session memory consolidation, but the wiki notes the review surface (Console diff) implies ongoing human spot-checking. If the diff review is skipped entirely, memory can drift. Is there an eval or coverage criterion that would let teams skip human review — and if so, what does it look like?

2. **What is the right skill granularity at the 1,000–10,000 skill scale?** The wiki documents the clean cases: hundreds of skills work fine; 100,000 skills break the index-tier. But the messy middle (1K–10K skills, typical of a large team's monorepo) isn't addressed. Do teams shard by team/domain? Use separate harness instances? Accept degraded precision? This practical question has no answer in the current wiki.

3. **Does shared org-wide memory undermine the "fresh perspective" case for subagents?** The wiki's strongest argument for subagents is a clean context (code reviewer who hasn't seen the author's reasoning). But in Managed Agents, both orchestrator and subagent can read from the same org-wide memory store. If the critic has absorbed the creator's past patterns via shared memory, does the fresh perspective actually exist?

4. **Is the Bitter Lesson asymmetric across harness components?** The wiki documents the Bitter Lesson eroding elaborate harness engineering — RAG pipelines, planner-executor splits. But the Managed Agents section describes increasingly sophisticated harness infrastructure (brain/hands decoupling, event logs, vaults). Does the Bitter Lesson apply uniformly, or does it selectively erode certain harness layers (retrieval, tool routing) while others (sandboxing, observability, credential management) remain durable?

5. **Can the communication breakdown problem in multi-agent systems be eval'd?** The wiki identifies communication breakdown (subagent produces correct result but mis-reports it to the orchestrator) as a distinct failure mode separate from task failure. Current eval patterns (grader types, hill-climbing) test final output quality. Is there a systematic way to eval communication fidelity — the gap between what the subagent knew and what the orchestrator received?
