## ❓ Open Questions

1. **When does harness investment become net-negative?** The wiki argues "build to delete" and "thin harness" while also describing increasingly sophisticated infrastructure (brain/hands decoupling, event log durability, credential isolation, vault memory). No framework distinguishes harness layers that are durable investments (security, observability) from those the model will absorb (retrieval, routing). Engineering leads deciding where to invest have no principled guide.

2. **How should memory quality itself be evaluated?** `evals-and-graders.md` covers task output evaluation thoroughly. The Dreaming architecture produces a memory store diff as accountability, but no eval framework for memory quality exists — e.g., coverage (important patterns captured?), precision (no false memories?), freshness (stale entries pruned?). The 97%/6× production results are outcome metrics, not diagnostic ones.

3. **What is the right granularity for subagent boundaries?** The wiki covers *when* to use subagents (parallelism or fresh perspective) but not *how fine-grained* those boundaries should be. The communication breakdown failure mode implies more boundaries introduce more coordination risk. No guidance exists on the coarse-vs-fine boundary tradeoff as models improve at holding more context.

4. **Can autoresearch close the eval saturation loop without humans?** The wiki flags that static benchmarks get saturated at autoresearch speeds and recommends pulling from production data. But no source describes a mechanism for autonomously evolving an eval suite. If humans must continuously update evals, autoresearch remains human-bound at the eval layer.

5. **What changes about security posture in BYOC (bring your own compute) architectures?** The Managed Agents brain/hands decoupling is described as improving security (credentials in vaults, no co-location with inference). But BYOC (released May 2026) transfers tool execution to developer infrastructure. The wiki does not address which security responsibilities shift to the developer in BYOC mode — credential isolation, network boundaries, audit logging, container hardening — or how to audit them.
