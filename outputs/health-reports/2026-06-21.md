## ❓ Open Questions

1. **When is Dreaming safe to run without human review of the diff?** The wiki documents Dreaming's non-destructive clone-before-write pattern and the Console diff as the accountability mechanism. But it never specifies what eval criterion or coverage threshold would make human review of the diff unnecessary. Is there a signal that a team's memory architecture is mature enough to run fully autonomously — or is human review of memory changes a permanent requirement?

2. **What is the correct skill architecture for the 1K–10K skill range?** The wiki covers the clean extremes: hundreds of skills work fine; 100,000 skills break the index-tier. The 1K–10K range — typical for a large multi-team engineering org — is unaddressed. Do teams shard skill indexes by team/domain? Use separate harness instances per product area? Accept reduced precision and compensate with better evaluation? The practical guidance is missing.

3. **Does the Bitter Lesson apply uniformly to all harness layers, or only some?** The wiki simultaneously argues thin harnesses (Bitter Lesson erodes RAG, planner-executor, memory stacks) and describes increasingly sophisticated managed agent infrastructure (brain/hands decoupling, event log durability, vaults, credential isolation). The wiki never articulates which harness layers are durable investments (sandboxing, observability, credential management) vs. which are transient (retrieval, routing, context management). This distinction is actionable for engineering leads deciding where to invest.

4. **Can multi-agent communication quality be eval'd independently from task quality?** The communication breakdown failure mode (subagent completes task correctly but mis-reports to orchestrator) is identified as a distinct failure from task failure. Current eval patterns test final output quality — they would pass if the orchestrator happened to recover from a bad handoff. Is there a systematic way to instrument and evaluate the fidelity of agent-to-agent communication — and would such evals require dedicated output schemas for every subagent boundary?

5. **At what point does shared org-wide memory undermine subagent independence?** The "fresh perspective" argument for subagents assumes the critic has seen nothing the creator has seen. In Managed Agents, both share org-wide memory. If the critic's memory was shaped by previous sessions with the same creator patterns, the clean context is partly an illusion. The wiki identifies this tension but doesn't address when or how to scope per-role memory to preserve genuine independence.
